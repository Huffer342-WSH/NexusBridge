# qB 任务恢复

## 目标

当 qB 任务被删除但磁盘文件仍存在时，根据 torrent 文件结构重建同一任务，不移动、复制或重命名磁盘文件。

## 数据流

```text
文件或目录 -> 文件大小多重集合 -> 数据库索引 / 站点搜索 / torrent URL
唯一 torrent -> paused 添加 -> qB 内部路径映射 -> 强制校验 -> 开始做种
```

| 模块 | 作用 |
| --- | --- |
| `file_manager.go` | 浏览文件、标记现有 qB 归属并扫描候选。 |
| `torrent_size_index.go` | 查询和手动重建大小倒排索引。 |
| `recovery.go` | 匹配 torrent、添加任务、映射路径和校验。 |
| `recovery_batch.go` | 串行执行扫描出的唯一候选。 |
| `storage/torrent_files.go` | 保存 torrent BLOB 及文件大小索引。 |
| `qbittorrent/torrents.go` | 添加、重命名、校验、启动和删除任务。 |

## 匹配

- 数据库、站点搜索和直接 URL 最终都要求文件数量、总大小及重复文件大小次数一致。
- 大小索引只缩小候选范围；执行前仍重新解析 torrent 并验证完整集合。
- 候选不唯一时不得自动恢复。网页搜索默认关闭，只在用户启用时作为数据库兜底。

## 安全边界

- 添加任务时使用目标父目录、`root_folder=false`、`autoTMM=false`、暂停并跳过初始校验。
- 路径调整只调用 qB 的文件重命名接口，不修改磁盘结构。
- 映射完成后显式强制校验；只有完整且暂停的任务才能自动开始做种。
- 校验失败时保留唯一暂停任务，由用户选择启动或仅删除 qB 任务。
- 删除恢复任务必须使用 `deleteFiles=false`；批量执行串行处理，单项失败不阻断后续项。
